**6. Should fix · verified — context extraction can certify unusable arrays**

**7. Should fix · verified — completed rows can permanently block recovery of missing states**

**Case:** a completed row batch exists, but its state file is missing → resume raises `AssertionError` instead of rebuilding it.  
State files are written directly, without atomic replacement or an explicit state-file `fsync`, before rows become durable.  
Resume checks only the shard’s keys, so readable keys can also conceal damaged array members until finalization.  
**Fix:** write shards atomically, validate their arrays before skipping batches, and rebuild missing states from stored IDs.

**9. Should fix · verified · shared — hashing allocates an entire state file**

[rows.py:275](/Users/brendon/persona-manifolds/manifold-persona/src/manifold_persona/rows.py:275)

`file_sha256()` calls `read_bytes()`, so hashing requires a contiguous allocation equal to the file size.  
**Case:** the full reply array requires **6.04 GiB** per hash, or **12.08 GiB** after float32 promotion.  
On a machine without that available memory, verification can fail after generation or during archival; I did not reproduce a full-size OOM.  
**Fix:** hash fixed-size chunks.
