# RESEARCH.steering.md

**Why a second context.** `RESEARCH.md` governs the geometry track and states as stable facts:
`data/` is read-only, runs do no re-extraction, all analysis is local CPU/numpy, no CUDA, no vLLM.
Every one of those is false for the steering track, which generates new responses with forward
hooks on a rented GPU and calls an external API. Different data, different environment, different
off-limits rules — so a separate context rather than an edit. `RESEARCH.md` is untouched and still
governs `output/manifold_h1-2/`, `output/per_persona_*`, and `output/per-persona-entropy/`.

**Project:** manifold-persona, steering track — does an intervention that follows the persona
manifold behave differently from the linear Assistant Axis? Replicates the role-susceptibility
evaluation of arXiv:2601.10387 §3.2.1 and adds two targeted arms. Roadmap H2 in `DESIGN.md`.

## Data

- **Read-only inputs:**
  - `data/embeddings_roles_resp240/` — response-token activations, Qwen2.5-3B-Instruct, layer 19
    (index 0, published pre-thinned), 331,200 records = 276 roles × 5 instructions × 240 questions.
    Source of role centroids, the Assistant Axis, and the fitted curve.
  - `../assistant-axis/data/roles/instructions/*.json` — 276 role files, 5 system prompts each.
  - `../assistant-axis/data/roles/role_list.json` — 275 roles + descriptions.
- **Generated by this track:** steered response text. Written **only** under the output root, never
  under `data/`.
- **Not available:** the paper's 50-role susceptibility system prompts (Appendix D.1.1 says they
  were regenerated for that eval and they are not in the repo); the Shah et al. jailbreak dataset;
  LMSYS-Chat-1M.

## Environment

- **Analysis / smoke test:** local MacBook (darwin, MPS), `.venv/bin/python` from the repo root,
  Python 3.9 — no `X | Y` runtime unions, no `match`.
- **Main run:** a **separate machine the user provides** (not this laptop), HF `transformers` with
  forward hooks. Not vLLM — vLLM does not expose the residual stream for intervention. The card is
  not assumed: every run measures and records its own generations/sec before committing to a grid.
- **Judge:** Anthropic API, `claude-sonnet-5`, Batches API, structured outputs. **Off by default.**
  Enabled only by `--judge` plus a non-empty `ANTHROPIC_API_KEY`; the smoke test is hard-capped at
  50 interactive calls and refuses to exceed it.
- **Output root:** `/Users/trinidad.borrell/Documents/Work/MARS-V/code/manifold-persona/output/steering-manifold/`
  Run dirs nest as `<output_root>/<YYYY-MM-DDTHH-MM>-<slug>/`.

## Code

- **Reuse, do not reimplement:**
  - `../assistant-axis/assistant_axis/steering.py::ActivationSteering` — layer resolution across

  - `src/manifold_persona/prompts_roles.py` — role record construction, `is_default` flag.
  - `extraction/generate_and_extract_roles.py` — the chunked, resumable, shard-checkpointed
    generation loop. The steering runner copies its checkpoint discipline.
  - `diagnostics/03_experiment1_shift_rank.py` — persona-shift rank diagnostic, re-run for its number.
- **Don't touch:** `data/`; any existing dir under `output/`; the causalab-port semantics in
  `manifold/tps.py`; anything under `exploratory/per_persona/`.

## Conventions

- Run dirs timestamped to the minute, never overwritten; each contains
  `figures/ data/ logs/ manifest.json REPORT.md`.
- Figures: matplotlib 300 dpi PNG, `figNN_<slug>_L19.png`.
- Plot functions defensive — a plotting failure logs and returns, never kills a run that already
  produced numbers.
- Seeds fixed and logged in `manifest.json`. Git sha + dirty flag recorded.
- Generation is greedy (`do_sample=False`), `max_new_tokens=128`, matching the resp240 cloud, so
  steered and unsteered text are comparable to it.
